# 多平台自媒体内容生产工作台 —— 开发说明书

> 版本：v0.2（已确认关键决策）
> 日期：2026-06-10
> 运行形态：桌面端（PC）本地应用
>
> **已确认决策**：① 不做自动发布；② 视频制作对接**剪映**（生成剪映草稿）；③ 封面**直连出图 API**。

---

## 1. 项目概述

### 1.1 一句话定位

一个运行在个人电脑上的**自媒体内容生产工作台**：针对小红书、抖音、微信公众号、微信视频号四大平台，按各平台的内容形态提供标准化制作流程（标题 → 内容 → 封面 → 视频），生成环节可自由选择调用 **AI 网页端**（如 ChatGPT 网页版）或 **AI CLI 工具**（如 Claude Code、Gemini CLI 等），支持混合编排与并行执行，并内置**评审评分模块**对生成的标题、内容、封面进行多维度打分与改进建议。

### 1.2 解决的核心问题

1. **多平台格式差异大**：同一选题在不同平台需要不同的标题风格、内容长度、封面比例、发布注意事项，人工切换成本高。
2. **AI 工具分散**：网页端（ChatGPT、Claude、Kimi 等）与 CLI 工具各有所长，目前需要人工在多个窗口/终端之间复制粘贴。
3. **产出质量不稳定**：缺少统一的质检环节，发出去才发现标题不吸引人、封面不合规。

### 1.3 非目标（明确不做）

- **不做自动发布**（已确认）：各平台风控严格，自动发布封号风险高。只做"生成 + 评审 + 一键复制/导出"，发布注意事项以清单形式提示用户手动发布。
- 不自研视频渲染：视频成片在**剪映**中完成，本系统负责生成脚本/分镜/素材并产出**剪映草稿**，用户在剪映里微调后导出。
- 不做多用户/云端协作，仅单机单用户。
- 不做素材版权检测（仅提示）。

## 2. 平台与内容形态矩阵

| 平台 | 模式 | 标题 | 内容 | 封面 | 视频 | 主要产物 |
|---|---|---|---|---|---|---|
| 抖音 | ① 视频 | ✅ | ✅ 口播稿/分镜脚本 | ✅ 竖版 9:16 | ✅ | 视频文件 + 标题 + 封面 + 话题标签 |
| 抖音 | ② 长文（图文随心推/头条体） | ✅ | ✅ 长文正文 | ✅ | — | 长文 + 标题 + 封面 |
| 抖音 | ③ 图片（图集） | ✅ | ✅ 图片文案 + 描述 | ✅ 首图 | — | 图集（多图）+ 文案 |
| 小红书 | ① 图文笔记 | ✅ ≤20字 | ✅ 正文 ≤1000字 + 标签 | ✅ 3:4 竖版 | — | 笔记图片组 + 文案 |
| 小红书 | ② 视频笔记 | ✅ | ✅ 口播稿 | ✅ 3:4 | ✅ | 视频 + 文案 + 封面 |
| 微信公众号 | 文章 | ✅ ≤64字 | ✅ 长文（富文本/Markdown） | ✅ 2.35:1 头图 + 1:1 缩略图 | — | 文章 HTML/MD + 封面 |
| 微信视频号 | 视频 | ✅ | ✅ 口播稿 + 描述 | ✅ 1080×1260（约 6:7） | ✅ | 视频 + 描述 + 封面 |

每个「平台 × 模式」组合定义为一条**制作流程（Pipeline）**，由若干**生成步骤（Step）**组成，每个 Step 可独立配置生成引擎。

### 2.1 通用步骤定义

| 步骤 | 说明 | 输入 | 输出 |
|---|---|---|---|
| 选题/素材录入 | 用户输入主题、关键词、参考素材、目标人群 | 人工输入 | Brief（结构化选题卡） |
| 标题生成 | 按平台风格生成 N 个候选标题 | Brief | 标题候选列表（默认 5 个） |
| 内容生成 | 正文 / 口播稿 / 分镜脚本 / 图片文案 | Brief + 选定标题 | 内容文稿 |
| 封面生成 | 直连出图 API 生成封面，自动派生平台尺寸 | 标题 + 内容摘要 | 封面图（平台对应尺寸）|
| 视频生成 | 生成口播稿/分镜/配音方案，并产出**剪映草稿**，在剪映中微调导出成片 | 内容文稿 | 剪映草稿 + 素材包 |
| 评审评分 | 对标题、内容、封面打分并给出修改建议 | 上述产物 | 评分报告 |
| 注意事项检查 | 平台合规清单核对（敏感词、外链、尺寸、时长等） | 全部产物 | 检查清单结果 |

### 3.2 技术选型（推荐方案）

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | **Electron**（备选 Tauri） | 需要内嵌/驱动浏览器（Web 适配器）且大量调用子进程，Node 生态最顺手；Tauri 更轻但 Rust 侧桥接成本高 |
| 前端 | React + TypeScript + Vite + TailwindCSS | 组件生态成熟，流程画布可用 React Flow |
| 本地服务 | Node.js（与 Electron 主进程同体或独立进程）+ Fastify | CLI 子进程（child_process）、流式输出转发（WebSocket）都很自然 |
| 浏览器自动化 | **Playwright**（persistent context 持久化登录态） | 驱动 ChatGPT/Claude 等网页端，登录一次长期复用 |
| 数据库 | SQLite（better-sqlite3） | 单机零运维 |
| 队列/并行 | p-queue / 自研轻量调度器 | 控制每个引擎的并发上限 |
| 图像处理 | sharp（裁切/加字/出多尺寸封面） | 封面按平台尺寸自动派生 |

> 备选形态：纯本地 Web 应用（Node 服务 + 浏览器访问 localhost），开发更快，但驱动外部浏览器和系统托盘体验略差。v1 建议 Electron。

## 4. 核心模块设计

### 4.1 生成引擎适配层（Provider Abstraction）

所有生成能力统一抽象为 Provider 接口，**每个步骤可独立绑定任意 Provider**：

```ts
interface GenerationProvider {
  id: string;                    // 如 "cli:claude", "web:chatgpt"
  kind: "cli" | "web" | "api";
  capabilities: Capability[];    // ["text", "image", "video-script", "image-gen"]
  maxConcurrency: number;        // 该引擎允许的并行任务数

  healthCheck(): Promise<ProviderStatus>;          // CLI 是否安装 / 网页是否已登录
  generate(req: GenerateRequest): Promise<GenerateResult>;
  generateStream?(req: GenerateRequest): AsyncIterable<Chunk>; // 流式输出到 UI
  cancel(taskId: string): Promise<void>;
}

interface GenerateRequest {
  taskId: string;
  stepType: "title" | "content" | "cover" | "video" | "review";
  prompt: string;                // 由 Prompt 模板引擎渲染好的最终提示词
  attachments?: FileRef[];       // 参考图、素材
  outputSchema?: JsonSchema;     // 要求结构化输出时使用（标题列表、评分 JSON）
  timeoutMs: number;
}
```

#### 4.1.1 CLI 适配器

- 以子进程方式调用本机已安装的 AI CLI，内置常见 CLI 的预设模板，也允许用户自定义任意命令：

| 预设 | 调用方式示例 |
|---|---|
| Claude Code | `claude -p "<prompt>" --output-format json` |
| Gemini CLI | `gemini -p "<prompt>"` |
| Codex CLI | `codex exec "<prompt>"` |
| 自定义 | 用户填写命令模板，如 `mytool --prompt {PROMPT} --out {OUTPUT_FILE}` |

- 命令模板支持占位符：`{PROMPT}`、`{PROMPT_FILE}`（长提示词写临时文件传路径，避免命令行长度限制和转义问题）、`{OUTPUT_FILE}`、`{ATTACHMENTS}`。
- 统一处理：超时杀进程、退出码判定、stdout/stderr 捕获、流式行输出转发到 UI。
- 安全：命令模板仅在用户显式配置时保存；执行前 UI 展示完整命令供确认（可设白名单后免确认）。

#### 4.1.2 Web 适配器（网页端调用）

- 基于 Playwright **persistent browser context**：首次使用时弹出真实浏览器窗口让用户手动登录（ChatGPT / Claude / Kimi / 豆包等），登录态保存在本地 profile 目录，之后自动复用。
- 每个网页端站点实现一个 Site Driver：

```ts
interface SiteDriver {
  siteId: string;                 // "chatgpt" | "claude-web" | ...
  loginUrl: string;
  isLoggedIn(page): Promise<boolean>;
  sendPrompt(page, prompt, attachments?): Promise<void>;
  waitAndExtractReply(page): Promise<string>;   // 等待生成完成并提取回复
  extractImages?(page): Promise<FileRef[]>;     // 提取生成的图片（封面场景）
}
```

- 风险与对策：
  - 网页 DOM 改版导致选择器失效 → Site Driver 以独立配置文件描述选择器，可热更新；提取失败时降级为"截图 + 人工复制"模式。
  - 平台风控/验证码 → 自动化全程使用有头模式（headed）+ 人类化输入间隔；遇到验证码暂停任务并通知用户人工处理后继续。
  - 网页端默认并发 = 1（同一站点串行，避免触发限制）；不同站点之间可并行。

#### 4.1.3 API 适配器（v1 必做）

封面已确认直连出图 API，因此 API 适配器升级为 v1 必做模块，分两类能力：

- **出图 API（封面生成主链路）**：统一 ImageProvider 接口，v1 内置预设：
  - OpenAI `gpt-image-1`（兼容 images API）
  - 火山引擎·即梦（国内访问稳定，中文文字渲染较好，推荐默认）
  - 通用"OpenAI 兼容"配置项（自定义 base_url + model，可接 SD WebUI / ComfyUI 的兼容网关等）
  - 请求参数：提示词（由封面 Prompt 模板渲染，含标题文案、风格、构图要求）、生成数量（默认 2 张候选）、原始尺寸；返回后经 sharp 裁切派生各平台尺寸（9:16 / 3:4 / 2.35:1 / 1:1 / 1080×1260）。
- **文本 API（可选）**：直连 OpenAI / Anthropic / 本地 Ollama，结构最稳定，优先用于评分模块（需要严格 JSON 输出）。

密钥统一存本地（系统 keychain，降级为加密文件），UI 提供连通性测试。

#### 4.1.4 剪映对接（视频生成链路）

已确认视频在**剪映桌面版**完成成片，本系统的视频步骤产出"可直接打开的剪映草稿"：

1. **生成阶段**（LLM）：输出结构化分镜表 JSON——每镜头的台词、画面描述、时长、字幕文案、转场建议；同时生成配音方案（TTS 文本分段）。
2. **素材准备**：分镜配图可复用出图 API 生成；用户也可在 UI 中替换为本地素材。
3. **草稿写入**：按剪映草稿格式（`draft_content.json` 等）组装工程文件，写入剪映草稿目录（Windows 默认 `%LOCALAPPDATA%/JianyingPro/User Data/Projects/com.lveditor.draft/`，macOS 对应路径，目录可在设置中自定义），包含：轨道（视频/图片轨、字幕轨、音频占位）、每段素材时长与转场。
4. **人工收尾**：用户打开剪映 → 草稿已就绪 → 微调（配音可用剪映内置 TTS"文本朗读"）→ 导出成片。

风险提示：剪映草稿格式为非公开格式，版本升级可能变动。对策：草稿写入模块独立封装并按剪映版本做适配开关；任何版本不兼容时**降级方案**为导出"素材包 + 分镜表（CSV/图文对照）"，用户在剪映"图文成片/手动拖入"完成，主流程不阻塞。

### 4.2 Pipeline 编排引擎

- 每条「平台 × 模式」流程定义为一个 **DAG（有向无环图）**，节点 = Step，边 = 数据依赖：

```yaml
# 示例：抖音-视频 流程定义（内置模板，用户可改）
pipeline: douyin-video
steps:
  - id: title
    type: title
    provider: cli:claude          # 每步独立指定引擎
    prompt_template: douyin/video/title.md
    output: { titles: string[5] }
  - id: content
    type: content
    needs: [title]
    provider: web:chatgpt
    prompt_template: douyin/video/script.md
  - id: cover
    type: cover
    needs: [title]                # 与 content 无依赖 → 可与 content 并行
    provider: api:jimeng          # 出图 API（即梦/gpt-image-1/自定义兼容端点）
    post: resize(1080x1920)
  - id: video
    type: video
    needs: [content]
    provider: builtin:jianying-draft  # 生成分镜+素材并写入剪映草稿
  - id: review
    type: review
    needs: [title, content, cover]
    provider: api:claude          # 评审默认用独立引擎，避免"自己评自己"
```

- 编排规则：
  1. 无依赖关系的步骤**自动并行**（如标题选定后，内容与封面同时跑）。
  2. 同一 Provider 的任务受其 `maxConcurrency` 限制排队。
  3. 任一步骤可单独**重跑**（保留多版本产物，用户挑选）。
  4. 步骤间传参通过模板变量：`{{steps.title.selected}}`、`{{brief.topic}}` 等。
  5. 支持人工卡点（human-in-the-loop）：如"标题生成 5 个 → 暂停等用户选 1 个 → 继续"。

### 4.3 Prompt 模板库

- 目录化管理：`prompts/<平台>/<模式>/<步骤>.md`，内置全套默认模板，用户可在 UI 中编辑覆盖。
- 模板内含平台规范约束（举例）：
  - 小红书标题：≤20 字、带 emoji、口语化、埋点击钩子；正文 ≤1000 字、结尾 3–6 个话题标签。
  - 抖音视频脚本：黄金 3 秒开头、口播稿按"钩子-内容-互动引导"结构、给出分镜表（镜头/画面/台词/时长）。
  - 公众号：标题 ≤64 字、给出摘要（≤120 字）、正文带小标题分段、配图位置建议。
  - 视频号：描述带话题 #，时长建议 ≤60s 的钩子前置结构。

### 4.4 评审评分模块

独立于生成引擎运行（建议绑定与生成方不同的 Provider），输出严格 JSON：

```jsonc
{
  "target": "title",            // title | content | cover
  "platform": "xiaohongshu",
  "scores": {
    "hook": 8,                  // 吸引力/点击欲（0-10）
    "platform_fit": 7,          // 平台风格契合度
    "clarity": 9,               // 信息清晰度
    "compliance": 10,           // 合规风险（敏感词/违禁词/广告法极限词）
    "seo": 6                    // 关键词/搜索友好度
  },
  "total": 80,                  // 加权总分（权重可按平台配置）
  "verdict": "pass",            // pass | revise | reject
  "issues": ["标题未包含核心关键词「xxx」"],
  "suggestions": ["可改为：……"]
}
```

- **标题评审**：对 N 个候选标题排序打分，UI 按分数排列供用户选择。
- **内容评审**：结构、节奏、平台规范、敏感词（内置本地敏感词/极限词词库做规则预检 + LLM 复检双层）。
- **封面评审**：走多模态（图片输入）Provider；评尺寸合规、文字可读性、视觉吸引力、与标题一致性。
- 评分不通过（< 阈值）时可一键触发"按建议重生成"。

### 4.5 注意事项（合规清单）模块

每个平台内置规则清单，产物完成后自动核对，规则分两类：

- **硬规则（程序校验）**：标题字数、正文字数、封面尺寸/比例、图片数量上限、视频时长/分辨率。
- **软规则（清单提示 + LLM 检查）**：诱导关注话术、外链、二维码、极限词（"最/第一/国家级"）、医疗/金融敏感领域、平台近期风控热点（清单可由用户维护更新）。

### 4.6 任务调度器

- 全局并发上限（默认 4）+ 每 Provider 并发上限。
- 任务状态机：`pending → running → waiting_human → succeeded / failed / cancelled`。
- 失败自动重试（可配次数，默认 1 次），网页端任务失败时附带页面截图便于排查。
- 所有任务事件经 WebSocket 推送 UI，实时显示每个步骤的流式输出。

## 5. 数据模型（SQLite 主要表）

```
projects        项目/选题（id, title, brief_json, created_at）
pipelines       流程实例（id, project_id, platform, mode, dag_json, status）
steps           步骤实例（id, pipeline_id, type, provider_id, status,
                prompt_rendered, started_at, finished_at）
artifacts       产物（id, step_id, version, kind[text/image/video],
                content/file_path, selected）
reviews         评分（id, artifact_id, provider_id, scores_json, total, verdict）
providers       引擎配置（id, kind, name, config_json[命令模板/站点/密钥引用],
                max_concurrency, enabled）
prompt_overrides 用户自定义模板（path, content, updated_at）
```

产物文件统一存 `workspace/<project>/<pipeline>/<step>/v<N>/`，便于直接拖拽使用。

## 6. UI 设计（主要页面）

1. **首页 / 项目列表**：新建选题（填 Brief：主题、人群、卖点、参考链接/素材上传）。
2. **平台模式选择**：勾选目标平台与模式（可多选，一个选题同时生成多平台版本，跨平台流程也并行执行）。
3. **流程工作台（核心页）**：
   - 左侧：DAG 流程图（React Flow），节点显示状态色（灰=待跑/蓝=运行中/黄=等待人工/绿=完成/红=失败）。
   - 节点上可直接切换该步骤的 Provider（下拉：cli:claude / web:chatgpt / api:... ）。
   - 中部：当前步骤的流式输出 / 产物多版本对比（v1 vs v2）。
   - 右侧：评分面板（雷达图 + 问题清单 + 一键按建议重生成）。
4. **引擎管理页**：CLI 检测（PATH 扫描 + 自定义命令测试运行）、网页端登录管理（一键打开登录窗口、登录态健康检查）、API Key 管理、各引擎并发设置。
5. **模板管理页**：按 平台/模式/步骤 编辑 Prompt 模板，支持变量插入与试跑预览。
6. **导出页**：按平台打包（文案 txt/md + 封面多尺寸 + 视频）、一键复制文案、发布注意事项清单（勾选确认式）。

## 9. 关键风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 网页端自动化被风控/改版 | 高 | 有头模式 + 人类化操作；Driver 选择器配置化热更；失败降级"打开页面人工复制" |
| CLI 工具输出格式不稳定 | 中 | 优先用各 CLI 的 JSON 输出模式；包一层输出解析容错 + 失败展示原文 |
| 剪映草稿格式非公开、随版本变动 | 中 | 草稿写入模块独立封装、按版本适配；不兼容时降级为"素材包 + 分镜表"人工导入 |
| 出图 API 中文文字渲染差/出图不可控 | 中 | 默认即梦（中文较好）；封面文字可选"API 直出"或"API 出底图 + sharp 叠加标题文字"两种模式 |
| 长任务并行导致机器卡顿 | 低 | 全局并发上限 + 任务可暂停；视频类任务默认独占 |
| 平台规则变化（字数/尺寸） | 低 | 规则集中在配置文件，UI 可编辑 |
| 账号安全（登录态/密钥） | 中 | 登录态仅存本地 profile；API Key 走系统 keychain；不上传任何数据 |
